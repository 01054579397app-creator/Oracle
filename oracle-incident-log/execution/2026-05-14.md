# Data Guard(ADG) 구성/승격 테스트 정리 (prmsdb asis→tobe)
한 줄 요약: asis(prmsdb 192.168.40.101/102)에서 tobe(prmsdb 192.168.40.106/107)로 ADG 구성 후, asis 종료 뒤 tobe를 primary로 승격(activate)하는 흐름을 원문 명령/설정 기준으로 재실행 가능 형태로 정리.

## 1. 테스트 목적
- asis DB ⇒ tobe DB로 adg 구성
- 데이터 일관성을 위해 asis DB 종료 후 tobe DB를 primary 로 승격(activate)하는 절차 확인

## 2. 핵심 명령/설정
- `backup as compressed backupset database                        format '/back/database_%s';`: standby 복구용 DB 백업
- `backup as compressed backupset current controlfile for standby format '/back/controlfile_%s';`: standby 용 controlfile 백업
- `backup as compressed backupset archivelog from scn 629649      format '/back/arc_%s';`: 지정 SCN부터 archivelog 백업
- `orapwd file='/sw/oracle/dbs/orapwtpdb' format=12 password=oracle`: password file 생성(파일 경로)
- `orapwd file='+DATA' format=12 password=oracle`: password file 생성(ASM 경로)
- `srvctl config database -d [primarydb] | grep -i password`: password file 경로 확인(ASM일 때)
- `asmcmd pwcopy [pwPATH] [copyPATH]`: ASM password file 복사
- `scp /data/back/* tsdb:/data/back`: standby로 백업본 전달
- `scp /sw/oracle/network/admin/tnsnames.ora tsdb:/sw/oracle/network/admin/`: tnsnames.ora 전달
- `scp /sw/oracle/dbs/orapwtpdb tsdb:/sw/oracle/dbs/orapwtsdb`: password file 전달
- `scp /sw/oracle/dbs/inittpdb.ora ts:/sw/oracle/dbs/inittsdb.ora`: init.ora 전달
- `*.audit_file_dest='/log/oracle/admin/tsdb/adump'`: standby pfile
- `*.control_files='/data/tsdb/control01.ctl'`: standby pfile
- `*.db_unique_name='tsdb'`: standby pfile
- `*.db_file_name_convert='/data/prmsdb/','/data/srmsdb/'`: standby pfile(name_convert)
- `*.log_file_name_convert='/data/TPDB/','/data/TSDB/'`: standby pfile(name_convert)
- `*.fal_client='tsdb';`: standby pfile(주석: 설정 안해도 됨 12c 부터)
- `*.fal_server='tpdb';`: standby pfile
- `startup nomount`: standby 초기 기동
- `restore controlfile from '/data/back/sc_10';`: controlfile restore(방법 1)
- `catalog start with '/data/back';`: 백업 catalog(방법 1)
- `restore database;`: DB restore(방법 1)
- `restore archivelog all;`: archivelog restore(방법 1)
- `recover database;`: 복구(방법 1)
- `restore controlfile from '/data/back/sc_353';`: controlfile restore(방법 2 [ asm일때 ])
- `alter database mount;`: mount
- `set newname for database to '/data/TSDB/%b';`: newname 지정(run 블록, 방법 2)
- `switch datafile all;`: datafile switch(run 블록, 방법 2)
- `select 'alter database rename file '||chr(39)||name||chr(39)||' to '||chr(39)||replace(name,'TPDB','TSDB')||chr(39)||';' from ( select name from v$tempfile union select member from v$logfile);`: rename file DDL 생성
- `alter database add standby logfile group 21~40 thread 1 size 200m;`: standby logfile 추가(표기 1)
- `alter database add standby logfile group 41~60 thread 2 size 200m;`: standby logfile 추가(표기 1)
- `alter database add standby logfile thread 1 group 21~40 size 200m;`: standby logfile 추가(표기 2)
- `alter database add standby logfile thread 2 group 41~60 size 200m;`: standby logfile 추가(표기 2)
- `alter system set log_archive_dest_2='service=tsdb lgwr';`: primary 파라미터
- `alter system set log_archive_dest_state_2='enable';`: primary 파라미터
- `alter database open read only;`: standby open read only
- `recover managed standby database disconnect;`: MRP 시작
- `srvctl stop database -db prmsdb`: asis DB 종료
- `startup mount`: tobe DB mount 기동
- `alter database activate standby database;`: standby→primary 승격

## 3. 핵심 이론 / 제약 / 주의점
- `*.db_file_name_convert`/`*.log_file_name_convert`: “이렇게 넣으면 셋뉴네임 필요없음. #ASM은 상관없음”
- `*.fal_client`: “설정 안해도 됨 12c 부터”
- `Standby DB add standby logfile`: “[Real-time APPLY 용 생성]”
- `log_archive_dest_state_2=defer → enable`: “ARC 프로세스 재시도 유도”
- `tnsnames.ora alias error`: “서비스가 빈칸으로 뜰 때는 primary DB를 종료 했다가 다시 켜야한다.”

## 4. 테스트 절차
1. (asis) RMAN 백업 수행
2. (asis) password file 생성(파일 또는 `+DATA`), 필요 시 `srvctl config database -d [primarydb] | grep -i password` 및 `asmcmd pwcopy`
3. (asis→standby) `scp`로 `/data/back/*`, `tnsnames.ora`, `orapw*`, `init*.ora` 전달
4. (standby) pfile 편집: `audit_file_dest`, `control_files`, `db_unique_name`, `db_file_name_convert`, `log_file_name_convert`, `fal_client`, `fal_server`
5. (standby) DB restore/recover
   - 방법 1: `startup nomount` → `restore controlfile from '/data/back/sc_10';` → `catalog start with '/data/back';` → `restore database;` → `restore archivelog all;` → `recover database;`
   - 방법 2 [ asm일때 ]: `restore controlfile from '/data/back/sc_353';` → `alter database mount;` → `run { set newname for database to '/data/TSDB/%b'; restore database; switch datafile all; recover database; }`
6. (standby) 필요 시 rename file DDL 생성: `v$tempfile`, `v$logfile` 기반 `alter database rename file ...`
7. (standby) standby logfile 추가(Real-time APPLY 용)
8. (primary) 파라미터 설정: `log_archive_dest_2`, `log_archive_dest_state_2`
9. (오류 대응) tnsnames.ora alias error 발생 시: primary 재기동, `log_archive_dest_state_2=defer → enable`, listener 재시작
10. (standby) MRP 시작: `alter database open read only;` → `recover managed standby database disconnect;`
11. (데이터 일관성) asis 종료 후 tobe 승격: `srvctl stop database -db prmsdb` → (tobe) `startup mount` → `alter database activate standby database;`
12. (이어서 할 예정) `tobe DB → tobe prmsdb 의 클린 DB로 TTS 이관`, `테이블스페이스 move하여 깔끔하게 정리`

## 5. 관찰 결과와 근거
- 결과: tnsnames.ora alias error 관련 조치 필요
  - 근거 로그/SQL/수치: “서비스가 빈칸으로 뜰 때는 primary DB를 종료 했다가 다시 켜야한다.”
- 결과: `log_archive_dest_state_2` 토글로 재시도 유도
  - 근거 로그/SQL/수치: “log_archive_dest_state_2=defer → enable : ARC 프로세스 재시도 유도”
- 결과: listener 재시작 수행(또는 필요)
  - 근거 로그/SQL/수치: “listener 재시작”
- 결과: 위 조치로도 실패할 수 있음(미해결)
  - 근거 로그/SQL/수치: “이걸 다 해도 안됄 때”

## 6. 해석
- (해석) 원문 흐름상 `log_archive_dest_2='service=tsdb lgwr'` 구성 과정에서 `tnsnames.ora alias error`(서비스 빈칸)가 발생했고, primary 재기동 및 `log_archive_dest_state_2` 토글/리스너 재시작으로 재시도를 유도하려는 의도로 보임.
- (해석) standby logfile 추가는 Real-time APPLY 목적이며, 이후 `alter database open read only;` + `recover managed standby database disconnect;`로 MRP를 기동하는 순서로 연결됨.

## 7. 문제점 / 미해결 이슈
- 남은 문제: tnsnames.ora alias error가 조치 후에도 해결되지 않는 케이스
  - 왜 문제인지: 원문에 “이걸 다 해도 안됄 때” 이후 해결 절차/근거가 없음
- 남은 문제: `tnsnames.ora` 항목(Standby/Primary 매핑) 상세 내용 부재
  - 왜 문제인지: “Standby / Primary tnsnames / Primary / Standby tnsnames”만 있고 실제 alias/서비스명이 없음

## 8. 다음 테스트 포인트
- `tnsnames.ora alias error` 발생 조건/재현 시점 기록(“서비스가 빈칸” 상태 확인 포함)
- `log_archive_dest_state_2=defer → enable` 적용 전/후 차이 확인(ARC 재시도 유도 결과)
- listener 재시작 전/후 차이 확인
- standby logfile 생성(21~60, thread 1/2, size 200m) 실제 적용 여부 확인
- `recover managed standby database disconnect;` 수행 여부 및 이후 상태 확인
- `alter database activate standby database;` 수행 후 승격 상태 확인

## 9. 30초 복습용 핵심 5줄
- asis→tobe ADG 구성: RMAN 백업 + 파일 전달 + standby pfile 편집 + restore/recover.
- standby는 Real-time APPLY용 standby logfile(21~60, thread 1/2, 200m) 추가.
- primary는 `log_archive_dest_2='service=tsdb lgwr'`, `log_archive_dest_state_2='enable'` 설정.
- `tnsnames.ora alias error` 시 primary 재기동/`defer→enable` 토글/리스너 재시작을 시도.
- 데이터 일관성: asis 종료 후 tobe에서 `alter database activate standby database;`로 primary 승격.
