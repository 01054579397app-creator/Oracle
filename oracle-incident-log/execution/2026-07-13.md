# Oracle Incident Log - execution


- [2026-07-13 14:11:59] Oracle Incident - execution
  - 질문 맥락: AS-IS의 UTL_HTTP HTTPS 서비스를 TO-BE에서 그대로 유지하려면 일반 DB 권한 외에 무엇을 이관해야 하는지 구체적인 이관 대상 요청
  - 에러 메시지: 오류 없음. 기존 답변이 Oracle 전체 권한 종류로 범위를 잘못 확장하여 UTL_HTTP 서비스 이관 항목으로 재정리
  - 원인 가설: 서비스 유지에는 ACL 외에도 PL/SQL 호출 코드와 Wallet 경로, OS Wallet 파일, CA/클라이언트 인증서와 개인키, 인증정보, Scheduler 실행정보, DNS/방화벽/라우팅/프록시, 외부 서버의 TO-BE 출발지 IP 허용, Oracle OS 파일 권한을 함께 이전해야 한다.
  - 권장 조치: AS-IS에서 서비스 계정/PDB/URL/포트/호출 패키지/Wallet 경로/Wallet 파일/인증서/작업 스케줄/네트워크 허용 정책을 인벤토리화한다. TO-BE에는 DB 객체와 ACE를 반영하고 Wallet 디렉터리를 안전하게 복제하거나 재생성한 뒤 소유권과 권한을 설정한다. DNS, 방화벽, 프록시, 외부 서버 IP allowlist를 TO-BE 기준으로 변경한다.
  - 검증 항목: TO-BE 실제 서비스 계정과 PDB에서 동일 URL에 UTL_HTTP 호출하여 HTTP 응답을 확인하고, 실제 SOAP 요청과 Scheduler Job까지 실행한다. AS-IS/TO-BE ACL 및 orapki wallet display 결과와 코드 내 URL/wallet_path를 비교한다.
