# Oracle Incident Log - execution


- [2026-08-13 08:57:42] Oracle Incident - execution
  - 질문 맥락: TAF 및 TAC 구성 테스트 프로그램의 구조, 실행 방법, 결과 판독법 분석
  - 에러 메시지: 실행 요청은 하지 않았으며 정적 분석 결과: TAC_EXPLICIT_TX.exe가 COMMIT 성공 문구를 출력하지만 실제 Commit 호출이 없음
  - 원인 가설: 두 프로그램은 ODP.NET Unmanaged Driver 19.28 기반이다. ConnectionPool 프로그램은 3초마다 새 논리 연결로 인스턴스명을 조회하여 풀/FAN 재접속을 관찰한다. EXPLICIT_TX 프로그램은 20건 DML 후 장애 유도 대기 구간을 제공하지만 Commit 호출이 없어 연결 종료 시 미커밋 로컬 트랜잭션이 롤백된다.
  - 권장 조치: ODAC19.28 odp.net4와 기본 클라이언트를 관리자 권한으로 설치하고 C:\trace를 생성한다. 두 EXE별 config의 호스트, 포트, 서비스명, 최소권한 테스트 계정을 수정한다. TAC용 서비스는 FAILOVER_TYPE=AUTO, COMMIT_OUTCOME=TRUE, NOTIFICATION=TRUE 등 서버 속성을 검증한다. tac_test 테이블을 준비한 뒤 ConnectionPool은 인스턴스 전환을 관찰한다. EXPLICIT_TX는 현 바이너리로 커밋 성공을 검증할 수 없으므로 Commit 구현 후 사용한다.
  - 검증 항목: srvctl config service 및 ALL_SERVICES에서 서비스 속성을 확인한다. ConnectionPool 출력의 INSTANCE_NAME 전환과 오류 여부를 확인한다. EXPLICIT_TX는 실행 전후 별도 세션에서 tac_test의 COUNT, COUNT(DISTINCT id), MIN/MAX(id)를 조회하고 ODP.NET trace를 확인한다. 현재 PC는 .NET Framework 4.8.1 이상이나 ODAC 레지스트리 등록과 C:\trace가 없다.
