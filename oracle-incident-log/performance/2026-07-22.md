- 주제: Management Pack 비활성 상태에서 통계 수집과 Statspack 대체 사용
- 질문 맥락: `CONTROL_MANAGEMENT_PACK_ACCESS=NONE`으로 Diagnostic/Tuning Pack을 비활성화하면 AWR을 사용할 수 없는 환경에서, 통계 수집 테스트와 주기적 성능 스냅샷을 추가 비용 없이 수행하는 방법을 확인.
- 오류 메시지: 없음
- 원인 가설: 통화 내용에서 옵티마이저 통계 수집(`DBMS_STATS`), 일반 성능 통계 수집(`STATISTICS_LEVEL`), AWR 스냅샷, Statspack 스냅샷이 혼용됨. `DBMS_STATS`의 객체/스키마/DB 통계 수집은 Management Pack과 별개이며 `NONE`에서도 실행할 수 있음. 반면 AWR/ADDM/ASH는 Diagnostic Pack 기능이므로 라이선스가 없으면 사용하지 않아야 함.
- 권장 조치: `CONTROL_MANAGEMENT_PACK_ACCESS=NONE`을 유지하고 `STATISTICS_LEVEL=TYPICAL`(또는 `ALL`) 및 `TIMED_STATISTICS=TRUE` 상태에서 Statspack을 설치해 사용. `@?/rdbms/admin/spcreate.sql`로 PERFSTAT 환경을 만들고, 테스트 전후에 `EXEC statspack.snap;`을 실행한 뒤 `@?/rdbms/admin/spreport.sql`로 두 스냅샷 사이의 성능 통계를 비교. 정기 수집은 PERFSTAT에서 `@?/rdbms/admin/spauto.sql`을 실행하면 `DBMS_JOB`으로 매시간 스냅샷을 예약하며 `JOB_QUEUE_PROCESSES>0`이어야 함. 실제 옵티마이저 통계는 별도로 `DBMS_STATS.GATHER_*_STATS` 또는 자동 작업 `auto optimizer stats collection`으로 수집.
- 검증 항목: `show parameter control_management_pack_access`, `show parameter statistics_level`, `show parameter timed_statistics`, `show parameter job_queue_processes` 확인. `DBA_AUTOTASK_CLIENT`에서 `auto optimizer stats collection` 상태 확인. Statspack 설치 오류 로그 확인 후 PERFSTAT의 스냅샷 목록과 `spreport.sql` 결과를 검증하고, `STATS$` 데이터 증가에 대비해 보존·삭제 정책을 마련. AWR 보고서 스크립트, `DBMS_WORKLOAD_REPOSITORY`, ASH/ADDM 기능은 호출하지 않음.
- 결론: "옵티마이저 통계 수집을 하려면 Management Pack이 필요하다"는 설명은 틀림. 유료 Pack이 필요한 것은 AWR 기반 성능 저장·분석이고, `DBMS_STATS`는 `NONE`에서도 가능함. AWR이 없는 환경의 주기적 성능 통계 대체 수단은 Statspack임.
