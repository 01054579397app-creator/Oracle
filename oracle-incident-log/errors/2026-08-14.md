- [2026-08-14 09:13:00] Oracle Incident - errors
  - 질문 맥락: DBHOME1/2와 NDBHOME1/2에 원격 접속하여 ACTIVE Physical Standby의 ADG 전송 및 적용이 정상 진행되지 않는 원인 진단
  - 에러 메시지: Primary DMHOME2의 GV$ARCHIVE_DEST_STATUS DEST_ID=2가 ERROR이며 ORA-12514: TNS:listener does not currently know of service requested in connect descriptor. Primary SWITCHOVER_STATUS=RESOLVABLE GAP. ACTIVE MRP0는 WAIT_FOR_LOG THREAD 2 SEQUENCE 26.
  - 원인 가설: Primary 양 노드의 active TNS 별칭은 192.168.40.191:11521, SERVICE_NAME=ACTIVE를 사용하지만 NDBHOME1의 11521 리스너에 ACTIVE 서비스가 등록되어 있지 않다. ACTIVE의 SERVICE_NAMES=ACTIVE이나 LOCAL_LISTENER가 공백이고, 호스트에는 Oracle listener가 11521에만 LISTEN 중이다. 기존 1521 연결이 남은 thread 1만 일부 전송되고 새 연결이 필요한 thread 2는 ORA-12514로 중단된 비대칭 상태다.
  - 권장 조치: ACTIVE의 LOCAL_LISTENER를 NDBHOME1의 11521 listener address 또는 해당 TNS 별칭으로 지정하고 ALTER SYSTEM REGISTER를 수행한다. listener services에서 ACTIVE/ACTIVE가 READY로 등록된 뒤 Primary DEST_ID=2를 재연결하고 thread 2 sequence 26부터 gap 전송 및 적용을 확인한다. ACTIVE는 Clusterware 등록 목록에 없으므로 운영 방식에 따라 CRS 관리 대상으로 등록할지 별도로 결정한다.
  - 검증 항목: NDBHOME1 lsnrctl services에 SERVICE_NAME ACTIVE 및 instance ACTIVE READY, Primary 두 인스턴스의 GV$ARCHIVE_DEST_STATUS DEST_ID=2 VALID/ERROR 공백, ACTIVE MRP0 APPLYING_LOG 또는 WAIT_FOR_LOG가 Primary current sequence를 추종, thread 1/2 received/applied sequence 증가, transport/apply lag 감소. 진단 중 원격 설정 변경이나 재기동은 수행하지 않음.
