- 주제: phpagedb1 LOG_ARCHIVE_DEST_2 활성화 후 ORA-16191/ORA-01017
- 질문 맥락: `ALTER SYSTEM SET log_archive_dest_state_2='enable'` 직후 TT00/TT04가 standby 로그인 오류와 ORA-16191을 반복 기록한 이유만 진단함.
- 최초 원본 오류: `/log/oracle/diag/rdbms/dmhome/DMHOME1/trace/DMHOME1_tt04_430355.trc`의 `OCISessionBegin failed`, `ORA-01017: invalid username/password; logon denied`. ORA-16191은 이 인증 실패의 후속 오류임.
- 송신 측 확인: phpagedb1의 DMHOME은 PRIMARY READ WRITE, `log_archive_dest_2=service=active`, `remote_login_passwordfile=EXCLUSIVE`, ASM 패스워드 파일 `+DATA_HOME/DMHOME/PASSWORD/pwddmhome.256.1240970879`을 정상적으로 열었음.
- 접속 대상 확인: TNS alias `active`는 `nphpagedb1:1521`, `SERVICE_NAME=DMHOME`으로 해석됨. 대상도 `remote_login_passwordfile=EXCLUSIVE`이고 SYS가 패스워드 파일에 존재함.
- 직접 원인: 양쪽 모두 패스워드 파일 사용 조건은 충족하므로, 대상이 반환한 ORA-01017은 송신/대상 SYS 원격 인증 정보 즉 패스워드 파일 불일치로 판단됨.
- 추가 구성 이상: 대상 nphpagedb1의 DMHOME은 PHYSICAL STANDBY가 아니라 `PRIMARY READ WRITE`이고 DB_UNIQUE_NAME도 송신 측과 동일한 `DMHOME`임. 따라서 현재 `service=active`는 standby를 가리키지 않으며 정상 Data Guard 전송 대상 구성도 아님.
- 조치 범위: 사용자 요청에 따라 원인 확인만 수행했고 파라미터, 패스워드 파일, DB 역할을 변경하지 않음.
