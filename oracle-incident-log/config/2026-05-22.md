# Oracle Incident Log - config

- [2026-05-22 14:30:19] Oracle Incident - config
  - 질문 맥락: RAC primary와 동기화된 standby DB에서 `v$archived_log` 일자별 count를 확인했을 때 2026-05-14까지 하루 약 200개 내외의 archived log가 생성되었고, 기존 online redo log가 thread별 3개, 각 200MB 수준이라 잦은 log switch 문제가 있었다. 이후 thread 1에 2GB redo log 10개, thread 2에 2GB redo log 10개, 총 40GB를 추가한 이유를 질의.
  - 원인 가정: redo log group 크기와 개수가 workload 대비 작아 log switch가 지나치게 자주 발생했고, RAC/Data Guard 환경에서 ARCH/LGWR/RFS/MRP가 switch, archive, transport, apply를 따라가지 못할 여지가 컸다.
  - 권장 조치: redo log를 2GB로 키워 log switch 빈도를 줄이고, thread별 10개 group으로 재사용 전 archive/apply 여유 시간을 확보한다. standby redo log는 online redo log 크기 이상, thread별 online group 수 + 1 이상인지 별도로 확인한다.
  - 검증 항목: `select thread#, group#, bytes/1024/1024 mb, status from v$log order by thread#, group#;`, `select thread#, group#, bytes/1024/1024 mb, status from v$standby_log order by thread#, group#;`, `select thread#, sequence#, first_time, next_time from v$log_history where first_time >= sysdate-7 order by first_time;`, `select process, status, thread#, sequence# from v$managed_standby;`, `select * from v$archive_gap;`
