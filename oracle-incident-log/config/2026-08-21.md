# Oracle Incident Log - config


- [2026-08-21 12:25:49] Oracle Incident - config
  - 질문 맥락: 추가 업데이트: LOG_ARCHIVE_CONFIG DG_CONFIG 사용 시 FAL_SERVER가 불필요한지와 Far Sync topology 권장값
  - 에러 메시지: 현재 ACTIVE FAL_SERVER=FSYNC 단일값이어서 FSYNC 경로가 ORA-16086/16055로 막혔을 때 Primary에서 gap을 직접 가져올 fallback이 없음.
  - 원인 가설: DG_CONFIG는 Data Guard 구성원 DB_UNIQUE_NAME 목록과 전송 허용/검증을 담당하고 FAL 서버 접속 순서를 제공하지 않는다. Oracle 19c Far Sync 예제는 Far Sync FAL_SERVER=Primary, terminal standby FAL_SERVER=FarSync,Primary로 구성한다.
  - 권장 조치: DMHOME/FSYNC/ACTIVE 모두 DG_CONFIG를 동일하게 유지. FSYNC는 FAL_SERVER=DMHOME_PROD 유지. ACTIVE는 FAL_SERVER=FSYNC,DMHOME_PROD로 구성하여 Far Sync 우선, Primary fallback gap fetch를 제공한다. Primary는 현재 역할에서는 FAL을 사용하지 않지만 role transition 대비 ACTIVE를 둘 수 있다.
  - 검증 항목: ACTIVE에서 gap 발생 시 FSYNC 실패 후 DMHOME_PROD로 FAL 요청이 이어지고 T1S87이 수신·등록되어 MRP WAIT_FOR_GAP이 해제되는지 확인.
